## 0. 决策基线(本次已确认 · 6 条)

| # | 决策 | 对方案的影响 |
|---|------|--------------|
| 1 | **暂时没预算 → 直接拨号(`wx.makePhoneCall`)、不录音** | 废弃 V1.0 的 TRTC/TCCC/PSTN/录制/ASR 全套,回到设计稿拨号方式 |
| 1a | **能否支持转文本?** | ❌ 真实通话内容**无法转文本**(直接拨号不录音、小程序拿不到通话音频,平台限制)。demo 用志愿者**手动录入**;后续可选"口述摘要转文字"(微信同声传译插件免费 / ASR 需预算) |
| 2 | **混元未配置时 → 不做 AI 总结,但仍可手动录入** | AI 预反馈改为**可选能力**:有 Key 才生成草稿,无 Key 直接空白表单手动填 |
| 3 | **上线前 Demo,暂不做隐私和加密** | 移除合规/加密相关实现,仅留"后续再做"备注 |
| 4 | **暂时只要个人统计** | 统计仅按当前志愿者(openid)聚合,不做团队口径 |
| 5 | **通话反馈在结束后自动跳出** | 采用 `pendingDial` 机制:拨号 success 后标记,返回小程序自动弹反馈表单 |
| 6 | **个体小程序** | 登录从"短信验证码"改为 **`wx.login` openid 静默登录**(个体无法用 `getPhoneNumber`/短信签名受限);部分高级能力受限,生产建议升企业主体 |

> ⚠️ **对 V1.0 的重大回退**:V1.0 因"真实录音"引入了 TRTC/TCCC/ASR/混元必选链路与外呼资质。现因"无预算+不录音+个体"全部砍掉,回到**设计稿 V0.2 的 `wx.makePhoneCall` 方案 + AI 预反馈(可选) + 自动弹反馈表单**。

**要点**
- 通话走设备自身蜂窝(`wx.makePhoneCall`),小程序不持音频、不录音、零平台费用。
- AI 预反馈(volunteer 拨出 + 时长 + 老人档案)由云函数调混元生成;**无 Key 时跳过,表单空白可手动填**(决策 2)。
- 统计仅按当前志愿者聚合(决策 4)。
- 无独立后台,逻辑全在云函数(决策 3 暂不做隐私/加密)。

## 3. 数据模型(在 V0.2 基础上,按本版精简)

## 5. 详细实现步骤(分阶段 · Demo 导向)

### 阶段 0 · 环境与资质(极简)
1. 注册**个体小程序**,取得 `AppID`;开通**微信云开发**,取得 `ENV_ID`。
2. (可选)若要做 AI 预反馈:在云函数环境变量配置混元 `SecretId/Key`(无则跳过)。
- ✅ 验收:开发者工具可预览;云开发控制台可见环境。

### 阶段 1 · 项目骨架与登录(P0)
1. 初始化「小程序 + 云开发」工程,目录见 §6。
2. 落地**设计变量**(配色见 §7)到 `app.wxss`。
3. 底部三 Tab 框架(联系人/统计/我的)+ 全屏登录路由。
4. 云函数 `login`:`wx.login` 拿 code → 云函数 `wx.getContext`/`openid` → 查/建 `volunteers` → 登录态(openid)存 Storage。
5. 登录态保持 + 退出。
- ✅ 验收:首次进入自动静默登录并进入列表;退出后再进需重新登录。

### 阶段 2 · 老人列表 / 详情 / 数据(P0)
1. 云函数 `seed-elderly`:灌入演示老人(含 `phone`);也可云控制台录入。
2. 列表:搜索、状态筛选、卡片展开。
3. 详情:基本信息、爱好增删、最近 3 条通话(倒序)。
- ✅ 验收:数据为真实库数据,可搜可筛。

### 阶段 3 · 拨号 + 自动反馈表单(P0,核心)
1. 拨号:`wx.makePhoneCall({phoneNumber: elderly.phone})`;success 后在 Storage 写 `pendingDial = {elderlyId, startTime}`。
2. 页面 `onShow` 检测 `pendingDial` → 自动打开反馈表单(决策 5)。
3. 云函数 `ai-prefeedback`(可选):有混元 Key 时,组装(老人档案+时长)→ 混元 → 草稿回填;无 Key 直接返回空,表单空白手动填(决策 2)。
4. 反馈表单:摘要/心情/标签/建议话题/时长(可改)→ 提交 → 新增 `call_records` → 更新 `Elderly.lastCallAt/priority` → 清 `pendingDial`。
- ✅ 验收:拨号后返回小程序自动弹表;有/无混元都能提交;提交后详情与统计更新。

### 阶段 4 · 个人统计(P0)
1. 云函数 `stats-aggregate`:过滤 `volunteerId == 当前 openid`,聚合累计/本周/今日/近 6 周/近期动态。
2. 统计页渲染(蓝 `#3898ec` 趋势图)。
- ✅ 验收:数字与本人通话记录一致。

### 阶段 5 · 我的 / 培训 / 技巧 / 反馈(P1/P2)
1. 志愿者资料卡、培训资料 CRUD+搜索、沟通技巧 CRUD、反馈平台提交。
- ✅ 验收:内容可增删改查并持久化。

### 阶段 6 · Demo 联调
1. 真机预览:拨号(走真实蜂窝)、返回自动弹表、统计刷新。
2. 无预算零成本验证全链路。
- ✅ 验收:核心流程在真机跑通。

> 隐私/加密、团队统计、真实录音转写、短信登录等列为**后续**事项,不在本期 Demo。

## 9. 风险与注意事项(精简)

- **个体主体发布限制(最高)**:个体小程序无法使用 `getPhoneNumber`、短信签名受限,且审核对"工具/辅助/表单收集"类敏感;本 Demo 可开发预览,**正式发布建议升级为企业/组织主体**。语音/外呼类敏感能力也需企业主体。
- **无法真实录音转写**:直接拨号不录音,通话内容无法转文本(平台限制),靠手动录入。
- **混元可选**:无 Key 时 AI 预反馈不生效,不影响主流程。
- **零预算**:本版全部用微信原生 + 云开发免费额度,无第三方按量费用。
- **隐私/加密**:本期 Demo 不做(决策 3),生产前必须补(加密存储、告知同意、最小化访问)。

## 10. 验收标准(总 · Demo)

5. 全程零预算、未接任何付费第三方服务(混元除外,可选)。
